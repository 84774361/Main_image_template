# 模板插件通用化整理路线

## 当前判断

这个插件已经不是最初的单模板 MVP。现在实际能力包括多 profile、CSV 驱动图层开关、产品/赠品自动排版、混合字体标题、PSD/JPG 导出、合并 PSD、产品名称映射和若干平台模板特例。

主要问题不是功能不够，而是通用能力和模板特例混在 `src/main-full.js`、`JDDaily/src/main-full.js` 两个大入口里。继续直接加 profile 会让后续维护越来越依赖记忆。

## 整理目标

把插件整理成三层：

1. 通用渲染内核：CSV 解析、图层查找、文字替换、智能对象替换、区域排版、导出、日志。
2. 模板能力模块：机制切换、人物切换、背景切换、赠品类型切换、标题注释优先级、产品阴影、PSD 清理。
3. 模板 profile 配置：路径、默认导出名、PSD 图层名、CSV 控制列、默认排版参数和平台特例。

整理后的目标是：新模板优先通过新增 profile 配置接入；只有出现新的渲染能力时，才修改通用代码。

## 保留原则

- `产品名称.csv` 继续作为产品身份和素材映射的权威来源。
- 视觉相关改动以 Photoshop 实际导出的 PSD/JPG 为准，不能只靠静态 JS 检查判定完成。
- 现有 profile 先复用、浅覆盖；不要因为批次平台不同就复制一整套相似逻辑。
- `src/main-full.js` 和 `JDDaily/src/main-full.js` 目前是并行入口，整理时要先确认真实加载面板，再决定是否同步。
- `txt.title` 的混排字体规则必须保留：只有 CJK 用中文字体，英文、数字、空格、符号走 LINE Seed。

## 建议分阶段

### 阶段 1：建立契约，不改行为

- 新增一份 profile 字段说明，列清楚 `paths`、`exportNameColumns`、`dailyMechanismSwitch`、`layerVisibilitySwitches`、`productAssetPriority` 等配置项。
- 新增一份 CSV 字段契约，区分通用字段、模板字段、兼容字段、废弃字段。
- 为每个现有 profile 做一张能力表：PSD、CSV、素材目录、机制数量、人物切换、赠品切换、产品排版、特殊字体。
- 只做文档和轻量命名整理，不改渲染逻辑。

### 阶段 2：抽离配置

- 把 `BASE_TEMPLATE_CONFIG` 和 `TEMPLATE_CONFIGS` 从入口文件中抽成独立模块或可复制的配置段。
- 为 profile 增加 `extends` 或显式继承说明，避免大段对象展开后看不清来源。
- 保留现有配置值不变，先让 diff 只体现搬迁，不体现逻辑变化。

### 阶段 3：抽离通用能力

优先抽最稳定、最少依赖 Photoshop 状态的函数：

- CSV 解析和行展开。
- 配置读取和 profile 解析。
- 文本分类、CJK/Latin 字体范围构造。
- CSV 控制列判断。
- 文件名和导出名生成。

暂时不要优先抽依赖 Photoshop 文档状态的函数，比如图层移动、智能对象替换、PSD 合并；这些更适合在测试样例稳定后处理。

### 阶段 4：模板预检

新增一个生成前预检：

- 检查 CSV 表头是否有无法识别的字段。
- 检查当前 PSD 是否缺少 profile 声明要求的关键图层。
- 检查 `daily.mechanism`、赠品类型、人物类型是否超出 profile 支持范围。
- 把问题输出到日志，并生成可读的失败清单。

这一步能显著提升通用适用性，因为新模板接入时可以先知道缺什么，而不是等 Photoshop 执行到一半失败。

### 阶段 5：统一入口

当 root 插件和 `JDDaily` 插件的能力边界明确后，再考虑合并入口：

- 如果两个入口只是默认 profile 和 UI 选项不同，可以合并成一个核心文件加两个面板包装。
- 如果两个入口仍有大量模板私有行为，先保持双入口，但共享配置和工具模块。

不要一开始就强行合并入口。当前代码已经服务多个真实批次，直接合并风险高。

## 第一批推荐动作

1. 先写 `docs/template-profile-contract.md`，把 profile 配置项定义清楚。
2. 再写 `docs/csv-field-contract.md`，把 CSV 字段分类清楚。
3. 然后只抽 `TEMPLATE_CONFIGS`，不动 Photoshop 行为。
4. 每一步都跑 `node --check` 和 `git diff --check`。
5. 任何图层开关、排版、导出清理相关改动，都用一个真实 Photoshop 导出样例验证。

## 不建议现在做

- 不建议马上把 9000 行入口拆成很多文件。UXP 加载和 Photoshop API 状态有坑，先抽纯配置和纯函数更稳。
- 不建议把所有模板特例改成自动推断。PSD 图层命名和 CSV 控制列仍然要作为明确契约。
- 不建议删除旧兼容字段。先标记废弃，再观察实际 CSV 是否还在用。
